# AMD GPU 환경의 애니메이션 렌더링 오류 대응

출시 후 AMD GPU 환경에서 채굴기 2종의 스프라이트 애니메이션이 깨진다는 제보가 있었습니다. 해당 건물들이 모두 3프레임 애니메이션인 점을 확인하여, 프레임 인덱스를 3으로 나누어 UV를 계산하는 과정에서 부동소수점 연산 오차가 발생한 것으로 판단했습니다.

이에 셰이더의 프레임 계산식을 보정했으며, 라데온 하드웨어 부재로 인한 재현 및 검증의 한계를 고려해 해당 건물들의 애니메이션을 4프레임으로 변경하는 예방 조치를 병행했습니다.

관련 셰이더: [`ShaderAnimated.shader`](./ShaderAnimated.shader)


## 증상

- AMD GPU 환경에서 채굴기 2종의 3프레임 애니메이션이 깨져 보이는 현상이 발생했습니다 (프레임 어긋남 또는 잘못된 UV 영역 샘플링).
- 타 GPU 환경에서는 정상 구동되는 점을 통해, GPU별 부동소수점 연산 정밀도 차이로 프레임 인덱스 계산이 경계값에서 어긋나는 것으로 판단했습니다.


## 원인 추정

라데온 환경을 직접 테스트할 수는 없었으나, 문제가 발생한 애니메이션들의 `totalFrames`가 모두 3이라는 점에 착안해 코드 분석으로 원인을 추론했습니다. 3처럼 2의 거듭제곱이 아닌 수는 부동소수점 오차로 프레임 경계가 어긋나기 쉬우며, 기존 `fmod` 연산의 GPU별 정밀도 차이가 라데온 환경에서만 렌더링 깨짐으로 나타난 것으로 파악했습니다.


## 조치

원인으로 `fmod` 정밀도 오차를 추정했으나 직접 검증할 수 없어, 계산식 보정과 확실한 회피책을 병행했습니다.

```
나머지 연산 보정 시도 (fmod → floor)
↓
라데온 하드웨어가 없어 직접 재현·검증 불가
↓
확실한 회피책으로 채굴기 2종을 3프레임 → 4프레임으로 변경
```

```hlsl
// ShaderAnimated.shader (frag) — 나머지 연산 교체
// Before: fmod (AMD 경계에서 부정확 추정)
frame     = fmod(frame, totalFrames);
float col = fmod(frame, frameColumns);

// After: fmod 대신 floor로 나머지 직접 계산
frame     = frame - floor(frame / totalFrames) * totalFrames;
float col = frame - floor(frame / frameColumns) * frameColumns;
```

- `fmod` 대신 `floor`를 활용한 나머지 연산식으로 교체해 부동소수점 경계 오차를 줄이도록 수식을 보완했습니다. 다만 AMD GPU 환경에서 직접 검증하지는 못했습니다.
- 확실한 예방책으로 문제 건물(채굴기 2종)의 스프라이트를 4프레임으로 재작업(`_TotalFrames = 4`)해 오차가 나던 3프레임 케이스 자체를 회피했습니다.


## 동작 확인

- 업데이트 적용 후 해당 현상을 제보했던 유저로부터 문제없이 동작한다는 피드백을 수신했습니다.
